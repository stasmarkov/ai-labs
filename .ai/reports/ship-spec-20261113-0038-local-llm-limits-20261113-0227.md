## Confirmed review findings

### Major

- `BENCHMARKS.md:1331`: the failover table and the "under 125 ms" claim do not match the committed `run.json`. Unreachable is 5-156 ms, model_missing 7-22 ms and timeout 1017-1134 ms. Fix: regenerate the table and the conclusion from `bench/results/llm/2026-11-12/run.json`.
- `app/Services/LlmEvalFigures.php:107`: nl-search `json_valid = 1 - validation_422.rate` counts failed and refused calls as valid. Fix: use `(queries - 422 - failed [- refused]) / queries`, or return null with a reason.
- `bench/llm-load.sh:294`: the describe loop pins the router IP from before `run.sh` starts, and `ddev restart` can change it, so "with load" figures can be measured with no AI load (task 11). Fix: re-resolve the IP after each restart, or start the loop per server, and refuse to write when `describes.completed == 0`.
- `bench/k6-sse.js:79`: per-stream chunks/s divides by the total duration, which includes the queue wait, so it measures queueing and not generation (3.3/s reported vs about 50/s real at level 16). Fix: divide by `duration - waiting`, report queue wait separately, and correct the "each stream gets a share" wording in BENCHMARKS and the guide.

### Minor

- `app/Support/LlmFailoverBench.php:62`: the timeout fault unloads once and uses short prompts, so entry points 2-4 depend on load timing. Fix: unload before each entry and use the long prompt the spec calls for.
- `tests/Feature/LocalLlmSmokeTest.php:126`: the moderation smoke test accepts 503 (task 12). Fix: require 200 and `data.status` in {classified, invalid}.
- `app/Support/LlmFailoverBench.php:171`: `run_errors` holds only the exception class, so the "redacted message" check is never done. Fix: read the stored `error_message` and assert it is redacted, or rename the field.
- `app/Support/LlmContextBench.php:52`: the truncation rule cannot detect a context shift (10688 tokens at `num_ctx` 8192 reported as not truncated). Fix: record the effective `context_length` from `/api/ps` and qualify the BENCHMARKS conclusion.
- `bench/llm-load.sh:204`: the warm-up uses listing 1, the same listing as the first measured stream, so the prefix cache lowers level-1 TTFT. Fix: use a warm-up id outside the measured range, or start the offset at 1.
- `app/Support/LlmSpeedBench.php:232`: TTFT silently becomes the total time when no content chunk arrives, and in-stream errors are lost. Fix: mark the sample as failed and record the error.
- `app/Services/LlmEvalFigures.php:113`: photo-vision accuracy is always null, with a reason that is wrong. Fix: map `body_type_agreement.rate` and name it in `accuracy_metric`.
- `app/Support/LlmFailoverBench.php:122`: a missing listing 1 is not caught in failover (it is swallowed as a generic `\Throwable` in speed), and any late exception discards all measured results. Fix: catch the specific not-found exception in one shared place, and write partial results or a checkpoint per section.
- `app/Support/LlmSpeedBench.php:205`: with `OLLAMA_KEEP_ALIVE=0`, the "warm" runs are cold and memory is null. Fix: force a non-zero `keep_alive` for the warm runs, or refuse to run.
- `app/Support/LlmBenchRedactor.php:18`: several credential shapes are missed (userinfo with no password, a password containing `@`, JSON-quoted `Authorization`/Basic, `x-api-key` and `api_key=`). Fix: extend the patterns and add a test for each shape.
- `bench/llm-load.sh:200`: `--models` values are written into `.env` unvalidated and unquoted (`${VAR}` expansion). Fix: check against `^[A-Za-z0-9._:/-]+$` and exit 2 on anything else.
- `app/Console/Commands/LlmBenchCommand.php:33`: there is no environment guard, and the command unloads every model on the shared Ollama and lifts rate limits. Fix: refuse to run outside `local` unless an explicit flag is given.
