# Ship report: spec-20261112-2146-moderation (SL-26 listing moderation classifier)

## Summary

SL-26 adds a listing moderation classifier to the lab:

- `POST /api/moderation` and the lab page at `/ai/moderation`.
- `ModerationFacts`, which computes the median price, the price ratio, VINs, the reported-VIN register and an injection pattern.
- `ModerationAgent` and `ModerationService`, which retry once and record an `invalid` status and an `ai_runs` row for each attempt.
- The `moderation:make-set` and `moderation:eval` commands, a guide at `/ai/guides/moderation`, a settings row and a BENCHMARKS section.

All four gates pass, with 2294 tests green. The live acceptance walk on Ollama qwen3.5:9b resolved end to end.

The slice is not ready to ship:
- Two converge gaps from round 2 (tasks 11 and 12) are unbuilt.
- Review confirmed three distinct major findings (four reports, one of them filed twice).
- All the work is still uncommitted on `master`.

## Confirmed review findings

### Major

- `app/Ai/ModerationAgent.php:39` — When `--provider` names a provider other than the configured one, `moderation:eval` drops the pinned `--models`. Every model then runs on that provider's default model, but the results are still filed under the requested model names, and `thresholdFor()` looks up the wrong key. This was reported twice, as correctness and as design. The design report adds that the command does no model validation, unlike `NlEvalCommand`. Fix: honour `$pinnedModel` whenever one is given, even under a provider override, or reject `--models` combined with a cross-provider `--provider`. Also validate the names against the provider's allowed models.
- `app/Services/ModerationService.php:103` — The verdict comes only from the model's own `risk`. An injection that works, or a reported VIN, can come back as risky=false even though the facts already flag it. Fix: when `injectionPattern !== null` or `vinReported` is true, raise risk to at least 0.7 in PHP and add `other`/`reported_vin` before comparing with the threshold.
- `app/Services/LabModerationService.php:66` — `GET /ai/moderation` parses `bench/moderation/listings.v1.jsonl` on every request, so the page returns a 500 if the file is missing or malformed. Fix: move the four examples into a small committed fixture under `resources/moderation/`, or guard the load.

### Minor

- `app/Services/ModerationEvalScorer.php:49` — The figures at the threshold and the hard-negative FP use `result->risky`, which comes from the configured threshold, not the best-F1 one. This is the same issue as converge gap 11. Fix: compute both at `risk >= best_f1.threshold`, and keep the configured-threshold figures as a separate field.
- `app/Services/ModerationEvalScorer.php:85` — `best()` treats a null F1 as 0 and compares with `>=`, so a run where nothing scored reports "best at 0.9". Fix: skip points whose F1 is null, and return null when none has a value.
- `app/Services/ModerationFacts.php:47` — The injection guard checks only `description`. The VIN search reads the title too, and make, model and city also reach the prompt. This was reported twice, as correctness and as security. Fix: run the guard over title, make, model, city and description.
- `app/Http/Requests/ModerateListingRequest.php:37` — A JSON-only body is not CSRF protection, because the framework's default CORS config allows `api/*` from any origin (`*`). With Ollama, third-party pages can start model runs. Fix: restrict CORS for these paths, or check `Sec-Fetch-Site`/`Origin` for every provider. `AssistantAskRequest` has the same problem.
- `app/Services/ModerationEvalSet.php:30` — Hard negatives are inferred from `id > ModerationSetBuilder::SAFE_GENERATED`. Fix: store an explicit `kind` or `hard_negative` field in `ModerationSetItem` and the JSONL.
- `app/Services/ModerationFacts.php:58` — The median cache key includes the `listing_id` the client sends, so the cache grows without bound. Fix: cache the aggregate for each make, model and year group and exclude the listing's own price in PHP, or resolve `listing_id` on the server.
- `app/Services/ModerationEvalScorer.php:183` — The scorer has its own copy of the percentile calculation. Fix: reuse `NlEvalScorer::percentile()`.
- `app/Providers/AiServiceProvider.php:62` — The reported-VIN register is loaded twice, and the two loads handle a missing file differently. Fix: load it in one shared place and inject it into `ModerationSetBuilder` and `ModerationFacts`.
