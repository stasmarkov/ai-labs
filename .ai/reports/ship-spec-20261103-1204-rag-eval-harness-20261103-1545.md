# Ship report: spec-20261103-1204-rag-eval-harness (SL-33, RAG eval harness)

## Summary

This slice adds `rag:eval`. It measures recall@k, MRR and threshold calibration on the live docs index, and with `--answer` it produces graded answers per model. It also adds a shared non-streaming `DocsAnswerService::answer()`, configurable chunk sizes with a mismatch guard, committed result runs, a BENCHMARKS section and learning-guide section 15. The main flow works on the live DDEV + Ollama stack, and every gate is green (677 tests). The build is not finished, though. 12 of 17 tasks are done and task 9 is incomplete. The four gaps from converge round 2 (14-17) were never built. Two major correctness defects are confirmed: published latency medians are skewed, and an in-stream Error writes no `ai_runs` row. A major security defect is also confirmed: `--force` deletes whatever path `--label` or `--output-dir` points at. All work is uncommitted on `master`.

## Acceptance

**The original scenario is not resolved end-to-end.** Running `rag:eval` against the live DDEV index and Ollama for recall and calibration, then with `--answer` for graded answers, works. The error exits, the chunk-size guard and the unchanged ask, search and parity behaviour were checked, but some of those checks fall short (see below).

What works live:
- Recall and calibration ran twice with identical results in about 4.0 s (NFR-1: under 30 s). The best threshold was 0.581951 (TPR 1, FPR 0.167). Text mode got 0/24 at every k, which matches the commit and is explained in BENCHMARKS.
- The answer run with qwen3.5:9b, graded by gemma4:12b, gave correctness 1.97, groundedness 2.00, cited 0.92, declined 5/6, false don't-know 0/24, failed 0 and TTFT 8750 ms.
- Invocation ids resolve at `/ai/runs/<id>` (HTTP 200, a completed `DocsAnswerAgent` row with ttft_ms set).
- MNC-1, MNC-2, MNC-3, NFR-2, and AC-1 through AC-7 and AC-10 hold.

Failing hops:
- **AC-8**: in `DocsAnswerService::answer()`, an in-stream SDK `Error` event throws inside the `foreach`. That abandons the generator, so no `ai_runs` row is written and the invocation id on the `Failed` result has no row (task 14). I found this by reading the code; I did not trigger a live failure.
- **AC-11**: when the embedding or the answer model is down, the command exits 1 and writes no files. But the message is generic and names no model: "Docs search is unavailable." or "Docs answering is unavailable right now." (task 15).
- **AC-9**: the result files and the BENCHMARKS section exist, but `bench/results/rag-eval` and the rest of the slice are untracked, so nothing is committed.
- **MNC-4**: the fingerprint matches, but parity was checked only on nginx-fpm. The other 5 servers were not run, because switching would restart the web container (task 9).
- AC-5: the refused-path scoring is implemented, but no command test covers it (task 16).

## Confirmed review findings

### Major

- `app/Services/RagAnswerEvaluator.php:58` / `:77`: the latency median counts no_context and refused_input rows, which never call a model. The TTFT median drops them, so the two figures cover different rows. The published 8641 ms should be 8997 ms. Fix: collect timing ids only for Answered, RefusedOutput and Failed results, or filter on ai_runs status. Then re-run and update BENCHMARKS.md. (Reported by both the correctness and the performance review.)
- `app/Services/DocsAnswerService.php:91`: an `Error` event throws inside the drain loop, so the SDK never fires AgentStreamed or AgentFailed and no `ai_runs` row is written. The run also stays in `AiRunRecorder::$runs` (the performance review flagged the build-up at `:522`). Fix: call `$recorder->failed($stream->invocationId, $e)` in the catch, or keep draining and then return Failed.
- `app/Services/RagEvalResultWriter.php:48` (path built in `app/Console/Commands/RagEvalCommand.php:271-281`): `--label` and `--output-dir` are never checked, so `--force` runs `deleteDirectory` on any path. For example, `--label=.. --force` wipes every committed result and `--output-dir=. --force` wipes the checkout. Fix: allow only `[A-Za-z0-9._-]+` labels with no `..`, use realpath to keep `--output-dir` under `bench/results`, delete only the known result files, and use a separate overwrite flag.

### Minor

- `app/Services/RagEvalResultWriter.php:48-49`: an overwrite deletes the old results before the move, so a failed move loses both the old and the new sets. Fix: rename the old directory aside, move the new one in, then delete the backup, or restore it if the move fails.
- `tests/Feature/RagEvalContaminationTest.php:60`: the text is normalized before `explode("\n")`, so the whole-line check for short answers never matches. Fix: split the raw text into lines first, then normalize each line.
- `app/DTOs/RagModelReport.php:101`: `mean([])` and an empty citation rate return 0.0 instead of null, which pulls the cross-run figures down. Fix: return null and skip nulls in `acrossRuns()`.
- `app/Services/RagEvalSet.php:168`: an evidence phrase made only of markdown characters normalizes to `""`, so every chunk counts as a hit. Fix: reject phrases whose normalized form is empty.
- `app/Console/Commands/RagEvalCommand.php:252`: with `--repeat > 1`, the count columns show only the last run while the score columns show medians. Fix: show sums or per-run ranges, or label the columns as last-run values.
- `resources/prompts/rag-grader.v1.md:12`: the decline rule is ambiguous for off-topic questions, so a correct decline can be scored either 0 or 2. Fix: pass `<expected_behaviour>decline</expected_behaviour>` and make the rules mutually exclusive.
- `app/Services/RagAnswerEvaluator.php:103`: it wraps a made-up RuntimeException to reuse a factory with a generic message, which hides the model name. Fix: add a dedicated `modelUnreachable($model)` factory (this also covers task 15).
- `app/Services/ThresholdCalibrator.php:44`: data errors raise `RagEvalOptionException`, so a bad eval set returns INVALID. Also, `RagRetrievalEvaluator.php:37-38` gives the `noKs()` message for an empty modes list. Fix: use a data exception and a modes-specific message.
