# Ship report: spec-20261029-2027-openlitespeed

## Summary

Adds OpenLiteSpeed (LSAPI) as a fourth switchable server, after nginx-fpm, apache-fpm and frankenphp. `ddev server openlitespeed` builds and starts a separate OLS container from a committed stash under `.ddev/servers/openlitespeed/`. The container sits behind the DDEV router on https://interview.ddev.site:8091, and the overlay keeps `webserver_type: nginx-fpm`, so the web container stays up but idle. `bench/parity.sh` and `bench/versions.sh` now know about the `litespeed` header token and the per-server default base URL. A parity snapshot is recorded, and BENCHMARKS.md, README.md and backlog.md are updated.

All 7 tasks are built (5 planned and 2 converge gap tasks). All 4 gates pass, and the live end-to-end journey on DDEV worked. One major review finding remains: the OLS PHP runs a different OPcache config from the DDEV web image, which skews the benchmark comparison this project exists to make. Fix it before shipping. None of the work is committed yet.

## Confirmed review findings

### Major

- `.ddev/servers/openlitespeed/Dockerfile:14`: lsphp keeps the image's OPcache defaults (memory_consumption 128, max_accelerated_files 10000, revalidate_freq 2). The DDEV web image uses 500, 1000000 and 0. This gives OLS fewer stat calls per request than the other servers, serves stale code for up to 2s, and leaves little headroom for the app's ~10.6k files. BENCHMARKS.md only records `OPcache true`. Fix: add a `zz-opcache.ini` that matches DDEV's values, or record the differences in the versions row.

### Minor

- `.ddev/servers/openlitespeed/conf/vhosts/interview/vhconf.conf:38`: the vhost-level front-controller rewrite with `[L]` runs before `public/.htaccess`, so `.htaccess` rules on non-file URIs never fire (`/listings/` gives 200, not 301). Fix: drop vhost lines 38-40 and rely on `.htaccess`, or document that only the vhost rules route requests.
- `.ddev/servers/openlitespeed/docker-compose.openlitespeed.yaml:9`: `TZ: ${TZ:-UTC}` always resolves to UTC, so the lsphp `date.timezone` does not match the web container (Europe/Kiev). Fix: pass DDEV's timezone value explicitly.
- `README.md:81`: the sentence claims unknown servers fall back to the part of the name before the first `-`, but `header_token` in `bench/parity.sh` rejects them. It also has a doubled "and". Two reviewers reported this. Fix: remove the fallback clause and use a comma.
- `.ddev/servers/openlitespeed/conf/vhosts/interview/vhconf.conf:36`: a client-sent `X-Forwarded-Proto: https` sets `HTTPS=on` with no trusted-proxy check. This only matters for direct access on `ddev_default`. Fix: restrict the rule with a `RewriteCond %{REMOTE_ADDR}` check for the router, or rely on TrustProxies.
- `.ddev/servers/openlitespeed/conf/httpd_config.conf:14`: `disableWebAdmin 0` leaves WebAdmin reachable on the shared network, against the spec's "configuration lives only in committed files". Fix: set `disableWebAdmin 1`.
- `bench/versions.sh:12`: the server -> base URL mapping and port 8091 are duplicated across parity.sh, versions.sh, the compose file, the docs and the tests. Fix: put the mapping in one place (for example `ddev server --url` or a shared bench helper).
- `tests/Feature/BenchScriptsTest.php:71`: the fixture writes `webserver_type: openlitespeed` without the `# server:` marker, so the tests take the fallback path instead of the one production uses. Fix: write the same overlay as `overlay_for` and key the curl stub on the marker.
- `tests/Feature/OpenLiteSpeedStashTest.php:10`: substring change-detector checks labelled AC-4/5/6, which tasks.md does not trace. They passed despite the `.htaccess` shadowing. Fix: add the file to the Traceability table as a static check, or replace it with a check that runs against the container.
- `.ai/specs/spec-20261029-2027-openlitespeed/tasks.md-E:1`: a stray, outdated macOS `sed -i -E` backup of tasks.md. Fix: delete it before committing.
