# Ship report: spec-20261110-2141-cloud-providers

## Summary

This change adds optional cloud providers (Anthropic, OpenAI, Gemini), chosen per feature: describe, NL search, docs answer, RAG grader and the two embeddings features. It also adds a lab provider selector, a `cloud-ai` rate limiter, a guard for switching embeddings, and a capability table in the providers guide. Pint, PHPStan, the full suite (1630 passed) and the debug scan all pass, and the acceptance pass found every AC holding on the live DDEV app.

It is not ready to ship:
- Tasks 6 and 9 are incomplete.
- Converge round 2 left seven gap tasks (17 to 23) unbuilt.
- Review confirmed a critical bug. `docs:index` embeds chunks with the listings embeddings provider but labels them with the docs model.
- No E2E regression test was written.
- All the work is still uncommitted.

## Confirmed review findings

### Critical

- `app/Services/DocsEmbeddingService.php:100`: `embedBatch()` calls `embedTexts()`, which falls back to the `embeddings-listings` provider and model, but stores the vectors under the docs model label. When the two providers differ, docs search silently returns wrong results. Fix: give `embedTexts()` a feature parameter, pass `DOCS_FEATURE`, and update the stale class docblock.

### Major

- `app/Repositories/EloquentSemanticSearchRepository.php:38`: the `embedding_model` filter runs after the HNSW scan, and iterative scan is off, so a mixed index gives truncated or empty results. Fix: add `SET LOCAL hnsw.iterative_scan = strict_order`, as the docs repositories do.
- `app/Services/NlSearchService.php:50`: `allowedModels()` always adds the Ollama id `gemma4:12b`, even when the provider is a cloud one, which leads to a 404 and then a 503. When an override is selected, the chosen model is also dropped without an error. Fix: offer `gemma4:12b` only when the resolved driver is ollama, and hide or disable the model control when an override is selected.
- `app/Console/Commands/RagEvalCommand.php:43`: `--grader` defaults to `gemma4:12b`, whatever provider `rag-grader` resolves to, so `AI_RAG_GRADER_MODEL` is never used. Fix: default to `(new RagGraderAgent)->modelName()`.
- `app/Http/Middleware/LimitCloudAi.php:31`: the cloud budget is per IP only, with no global cap, and the describe and NL search GET endpoints can be triggered from other sites. Fix: add a global per-minute or per-day `Limit`, and require a same-origin signal before a request may name a cloud provider.
- `app/Services/ListingEmbeddingService.php:26`: the listings service owns `DOCS_FEATURE` and the shared resolver, and its `$feature` defaults to listings, so any missed argument picks the wrong feature without an error. Fix: move embeddings resolution into `AiProviders` or a feature-parameterised service with no default.

### Minor

- `app/Ai/AiProviders.php:92` (and the `CLOUD` map at line 28): cloud status is decided by the entry name, not its driver, so a renamed or extra cloud entry counts as local and skips both the key check and the limiter. Fix: classify by `driver`, and drop the unused SDK-class column.
- `routes/catalog.php:33`: cloud embedding calls (semantic search, docs search, the docs-ask question embedding) bypass `cloud-ai`. This is the same issue as gap 17. Fix: also count the embeddings feature in the limiter, and attach the limiter to the search routes.
- `app/Ai/AiRunRecorder.php:231`: raw cloud error text, which can include a masked key and org ids, is stored and served by the public `/ai/runs/{id}` endpoint. Fix: store a sanitized category, or redact before saving.
- `app/Services/LabOverviewService.php:45`: Ollama reachability checks only the describe and embeddings-listings providers. Fix: check every feature's provider.
- `app/Services/DocsSearchService.php:69`: the index guard runs again on every iteration of the bench and calibration loops, and `DocsCachePairScorer` now depends on an index it never uses. Fix: check once at the entry points.
- `app/Services/SemanticBenchService.php:61`: the bench calls `nearest()` without the model label, so it measures a different query from production. Fix: pass `modelLabel()`.
- `app/Services/LabProviderService.php:26`: it reads `config('ai.providers')` directly instead of going through `AiProviders`, and the `enabledTextProviders` prop name is misleading. Fix: add `AiProviders::selectableTextProviders()`.
