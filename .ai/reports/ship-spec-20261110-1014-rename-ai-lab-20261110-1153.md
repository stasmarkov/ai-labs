## Confirmed review findings

Duplicate findings from the correctness, security and design passes are merged below.

### Major

- `app/DTOs/LabHome.php:38`: the page prop `'lab' => ['href' => ...]` overwrites the shared `lab` top-bar prop from `HandleInertiaRequests::share()`, which Inertia merges with a top-level `array_merge`. On `/` the layout renders an empty nav, no model tags, and "Ollama not used". `HomeLandingTest` asserts `lab.href`, which locks the bug in. **Fix:** rename the page prop (for example `labHref`), update `Home.vue` and `HomeLandingTest`, and assert that `lab.navigation` is present on `/`.
- `.ddev/commands/host/setup:65` (`set_key` at line 46): `set_key` deletes the `APP_NAME=` line and appends the new value at the end of the file, after `MAIL_FROM_NAME="${APP_NAME}"` and `VITE_APP_NAME="${APP_NAME}"`. phpdotenv then loads the literal string `${APP_NAME}`. This runs against the real `.env` in step 5 of `bench/rename-project.sh`. **Fix:** replace the value in place on its own line (sed or awk), and add a fixture with a `${APP_NAME}` reference after APP_NAME plus an assertion that the line order is kept.

### Minor

- `bench/rename-project.sh:106`: the preflight requires a clean tree, but the spec says to commit after verification. Committing first leaves bench defaults, parity and Mercure `cors_origins` pointing at `ai-lab` while the project is still `interview`. Also, `ddev describe` exits 0 for a stopped project, so the check at line 105 does not test that the project is running. **Fix:** agree on the order (commit the code, then rename in the same session), and check that the project is running via `ddev describe -j` status.
- `docs/manual-test.md:3`: it requires `docs/getting-started.md`, which was deleted after the negative test in task 12. **Fix:** `git checkout -- docs/getting-started.md` and apply the ai-lab URL (task 13).
- `bench/parity/frankenphp.txt:1` (and the other five files): the header says `base=https://ai-lab.ddev.site` with `captured=2026-11-05`. The `f840ff18` hash was measured only on frankenphp and copied to the others. **Fix:** re-capture on all six servers after the rename (task 10).
- `app/Services/LabHomeService.php:49-51`: the step labelled "Optional cloud keys" shows `AI_PROVIDER=ollama` and says the lab runs on Ollama, but the default provider is `fake-stream`, and the README says this switch is required. **Fix:** make this a required "Use local models" step, and keep cloud keys as a separate SL-51 note.
- `CLAUDE.md:11` and `CLAUDE.md:26`: it still says the database is MariaDB 11.8 and that tests use in-memory SQLite. The project uses Postgres 16, and tests use pgsql `testing` on `db`. **Fix:** update both lines.
- `resources/views/welcome.blade.php:1`: the view is no longer referenced but is kept only because it holds the Tailwind fingerprint in place, and nothing marks it as load-bearing. `docs/architecture.md:22` still describes `Route::view('/', 'welcome')`. **Fix:** re-baseline the fingerprint and delete the view, or document why it stays. Update `docs/architecture.md:22` either way.
- `tests/Feature/RenameTest.php:46`: `.ddev/commands/host/setup` and `ServerDefaultCommandTest.php` are allowlisted in full for `interview.ddev.site`. **Fix:** allow only the specific line or pattern, such as the `case` rule and the data-provider row.
