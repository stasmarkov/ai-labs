## Confirmed review findings

### Major

- `bench/suite.sh:79` (same issue in `bench/memory.sh:69`): `BENCH_DATE` defaults to today, which is the SL-06 folder, so a `--servers` run overwrites the committed SL-06 summaries. Fix: when `--servers` is given, default to `<date>-classic-vs-worker`, or exit 2 if the target summaries already exist (gap 11).
- `bench/run.sh:65`: `restore_env` puts `.env` back but does not restart the worker servers, so after a standalone run on frankenphp-octane or frankenphp-worker they keep serving production config with `DEBUG_ROUTES=true` and `/debug/*` stays reachable. Fix: for worker servers whose env was switched, run `ddev restart` (or `concurrency.sh default`) after restoring, and add a test for it.
- `bench/run.sh:110`: the new worker reload is followed by the existing restart at line ~265, which gives two (with the suite, three) container restarts per non-quick run. Fix: restart at line 110 only when line 265 will not run, or use `octane:reload` or the FrankenPHP admin `POST /frankenphp/workers/restart`.
- `bench/concurrency.sh:46`: the octane overlay (`override_config: true`) survives `ddev server <other>` and silently turns any server into Octane. Fix: drive the workers through env vars read by the daemon command, or have `ddev server` remove the bench overlays.
- `bench/concurrency.sh:53`: worker sizing edits `.ddev/web-build/Caddyfile.frankenphp`, a file that `ddev server` owns, in place. This causes drift resets, image rebuilds and backup carry-over, and it contradicts the "gitignored overlays" wording in AC-1. Fix: put `{$FRANKENPHP_WORKER_NUM:4}` and `{$...MAX_REQUESTS:500}` placeholders in the Caddyfile and set them from the overlay.
- `bench/suite.sh:63` (and `bench/summary.php:280`, `tests/Feature/BenchSuiteServersTest.php:82,90`): the baseline order is nginx-fpm before frankenphp, and a list with neither is refused. The spec says frankenphp, then nginx-fpm, then the first listed server, and the tests lock in the wrong rule. Fix: implement the spec order and correct the tests (gap 12). It does not affect the planned SL-08 list.

### Minor

- `bench/memory.sh:185/190`: results are rewritten after each case and never cleared at the start, so a failed later case leaves a partial file, or a previous run's file, that looks valid. The header also says a non-200 aborts the run, but the case runs to the end first. Fix: write to a temp file and move it into place only after all cases succeed, or fail fast.
- `bench/suite.sh:34` (message at `:54`): `--servers` as the last argument exits 1 with no message, because of the double `shift` under `set -e`. Duplicate servers are not removed. Fix: check `$# -ge 2` in the branch and deduplicate the list.
- `bench/summary.php:348`: `--tables` always prints an empty Timeouts table, which would go into BENCHMARKS.md for AC-5. Fix: skip the table when there are no `timeouts-*.json` files, as is already done for the memory table.
- `bench/run.sh:112` (same in `bench/memory.sh:100`): the ready-wait counts attempts, not seconds. The worst case is about 62 minutes against the documented 120 s. Fix: use a `SECONDS` deadline and cap curl's `--max-time` at the time left.
