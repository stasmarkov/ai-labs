# Ship report: spec-20261101-1822-octane-leak-lab (SL-07 Octane state-leak lab)

## Summary

SL-07 adds an Octane state-leak lab behind `DEBUG_ROUTES`. It has four `/debug/leaks/{scenario}` routes (dealer-scope, price-cache, number-locale, request-at-boot), each with a `leak` and a `fixed` mode, plus `/debug/worker` (pid, app_id, memory, worker_hits, first_seen_at, octane). It also adds `bench/leaks.sh`, a "State leaks" table in BENCHMARKS.md and section 7 of the learning guide (BR-30, BR-31, BR-32).

The feature works end to end. All gates pass (260 tests, 1394 assertions). The live nginx-fpm walkthrough and the out-of-process Octane Worker tests both behave as the spec says.

The build is not finished, though. 9 of 12 tasks are done. The three converge gap tasks (10–12) are not built, so the "All tasks checked" Done-when item cannot pass. There is also one major review finding in `bench/leaks.sh`: it can print a false "0/20". All SL-07 work is uncommitted on `master`.

## Confirmed review findings

### Major

- **`bench/leaks.sh:137`:** `count_leaks` falls back to `echo 0` if `jq` is missing, or if any one body is not JSON (for example an HTML 502). On a host without jq, every row prints a silent `0/20`, which reads as "no leaks anywhere". **Fix:** check `command -v jq` at startup and refuse if it is missing. Parse each response file on its own, so one bad body cannot zero the count.

### Minor

- **`bench/leaks.sh:127`:**
  - **Problem:** `fire()` deletes the A phase's status codes, so failed A requests are never counted. A broken A phase then reads as a clean `0/20`.
  - **Fix:** count non-200 codes after the A fire too, and refuse or annotate the row if any A request failed.
- **`bench/leaks.sh:58`:**
  - **Problem:** on frankenphp-octane without `--max-requests`, the script only runs `octane:reload`. That does not override a `DEBUG_ROUTES` value that was already in the daemon's environment at start. `cleanup()` also never checks that `/debug/*` is back to 404.
  - **Fix:** restart the daemon (as `bench/run.sh` does) instead of reloading, and assert a 404 in `cleanup()`.
- **`tests/Feature/LeakLabTest.php:125`:**
  - **Problem:** `phpunit.xml` does not pin `DEBUG_ROUTES`. With `DEBUG_ROUTES=true` in `.env`, or a `.env` left switched by an interrupted `leaks.sh`, the MNC-2 test fails and the provider resolves the leak singletons in every test app.
  - **Fix:** add `<env name="DEBUG_ROUTES" value="false"/>` to `phpunit.xml`.
- **`tests/Support/octane-worker.php:49-53`** (two reviewers reported this separately):
  - **Problem:** the helper prints all responses first and all `FakeClient` errors after them. If request A throws, the output becomes `[B, errorA]` and the tests compare against the wrong request.
  - **Fix:** record each request's outcome in order, by comparing the response and error counts after each `handle()` call.
- **`routes/debug.php:12`:**
  - **Problem:** with the flag off, a non-GET request (for example `POST /debug/worker`) returns 405 with an `Allow: GET, HEAD` header instead of the unknown-path 404. That breaks MNC-1 and reveals the hidden routes.
  - **Fix:** register `routes/debug.php` only when `config('app.debug_routes')` is true, or gate it in route-level middleware.
- **`app/Http/Controllers/DebugWorkerController.php:30`:**
  - **Problem:** `memory_get_usage(true)` reports memory in 2 MiB chunks, so it hides the price-cache growth the lab is meant to show.
  - **Fix:** also return `memory_get_usage()` as `memory_used_bytes`, and rename the real-usage value to `memory_reserved_bytes`.
- **`app/Debug/Leaks/LeakLabServiceProvider.php:21`:**
  - **Problem:** the bindings are gated once at boot, but the routes are gated on every request. If the flag is flipped at runtime, the route passes its guard and then fails with a 500 `Target class [lab.dealer.leak] does not exist`.
  - **Fix:** have the runner check `bound()` and return 404, or have both guards share one source of truth.
