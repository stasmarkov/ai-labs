# Ship report: spec-20261104-1944-export-offload (SL-11 export offload)

Date: 2026-11-04 22:19

## Summary

SL-11 adds a generated 50 MiB CSV export (`exports:generate`) and the `GET /exports/{id}?mode=offload|stream` endpoint. It also adds web-server offload configs for nginx (`X-Accel-Redirect`), Apache (`mod_xsendfile`), FrankenPHP (Caddy `intercept`) and OpenLiteSpeed (`X-LiteSpeed-Location`), plus a bench harness, 8 committed result files, a BENCHMARKS section and guide section 20.

Offload works end to end on all four servers: same sha256, 0 bytes sent by PHP. All gates pass. The feature is not ready to ship, for three reasons:

- AC-4 fails on OpenLiteSpeed. A stream-mode client disconnect is logged `aborted:false`, and PHP reads the whole file.
- Converge gap 14 (a test that stream mode flushes after every 64 KiB chunk) was not built.
- Review found three major issues: FrankenPHP `cpu_ms` is process-wide, the CPU baseline is taken too late, and the OLS direct-access rule can be bypassed with an encoded path.

## Acceptance

**Resolved: no.** I ran the original scenario live on nginx-fpm, apache-fpm, frankenphp and openlitespeed. Every step passed except one, listed under the broken hop below.

- Generate: 52,428,832 bytes, 206,340 rows, sha256 `74366ebf...`. A rerun replaces both the file and the record.
- Offload: 200 with the full file and a matching sha256 on all four servers, `X-Export-Mode: offload`, `bytes_sent_by_php=0`.
- Stream: identical bytes on all four servers, 2-6 MiB peak memory.
- Error cases: JSON 404 and 422, 429 from the throttle, and 404 when the debug gate is off.
- Direct-URL access to the exports never returned 200. Crafted offload-header paths were refused on Apache, FrankenPHP and OLS. nginx was not probed with crafted paths; it is covered only by `internal`+`alias` and `ExportOffloadConfigTest`.
- MNC-1..4 and NFR-1/2 passed. `.ddev/config.yaml` is unchanged and the asset fingerprint matches.

Broken hop:

- **AC-4 on openlitespeed.** A stream-mode client disconnect (`curl --max-time 3` and `--max-time 5`, each run twice) is logged `aborted:false` with `bytes_sent_by_php=52428832`. OLS keeps accepting PHP's writes after the client has gone, so PHP reads the whole file. nginx, Apache and FrankenPHP log `aborted:true` and stop reading. The AC-4 test uses a fake `AbortWatcher`, so the suite cannot catch this, and the gap is not documented in the spec or the guide.

Smaller deviations:

- On OLS, offload responses have `Content-Type: application/octet-stream` instead of the `text/csv` that the spec's Scope asks for. OLS uses the target file's MIME type. AC-2 still passes.
- Parity was re-run live only on nginx-fpm. The other five servers rely on the run recorded in `tasks.md`, plus 200 checks of `/`, `/listings` and `/healthz` on the four servers.

E2E regression test: none. The backend Laravel stack declares no browser e2e, so no AC-traced E2E test was written or run. Coverage comes from the PHPUnit feature tests (`ServeExportTest`, `ExportGenerateTest`, `ExportOffloadConfigTest`, `BenchExportLoadTest`, `ExportLoadResultsTest`).

## Confirmed review findings

### Major

- `app/Support/ExportDownloadLog.php:73-75`: on FrankenPHP, `cpu_ms` comes from `getrusage()` with RUSAGE_SELF. That counts the whole Caddy/PHP process, including other downloads and Caddy's file_server. The published FrankenPHP numbers (28.6 ms offload, 699.9 ms stream; `BENCHMARKS.md:683`, `:687`; `docs/learning-guide.md:941`) are artifacts of this, not real per-download costs. Fix: mark FrankenPHP CPU as not comparable and drop it from the doc, or measure per-thread CPU (`/proc/thread-self/stat`).
- `app/Support/ExportDownloadLog.php:27`: the CPU baseline is read in `begin()`, called from the controller, so framework boot, middleware, validation and the record lookup are left out. Spec Q8 says `cpu_ms` covers the whole request. Fix: read the `getrusage` baseline in `public/index.php` next to `LARAVEL_START`, then restate the offload-vs-stream CPU ratio in BENCHMARKS.md.
- `.ddev/servers/openlitespeed/conf/vhosts/interview/vhconf.conf:52`: the deny rule matches the raw `%{THE_REQUEST}`. A request like `GET /%5Fprotected_exports/listings.csv` or `//_protected_exports/...` slips past the rule but still maps to the context, which has `allowBrowse 1`. That breaks NFR-2. This has not been checked live. Fix: match on the decoded `%{REQUEST_URI}` gated by a variable set only on the internal redirect, set `allowBrowse 0` where possible, and add the encoded and double-slash variants to manual-test step 3.

### Minor

- `tests/Feature/ServeExportTest.php:211`: the AC-3 memory test's 16 MiB fixture already raises the peak, so a `file_get_contents` regression would pass. Fix: free the fixture, call `memory_reset_peak_usage()` before each request, and use the spec's 5 MiB file with a 2 MiB delta.
- `app/Services/ExportFileService.php:118`: `fwrite`/`fclose` results are not checked, so a short write still gets renamed into place with the full byte count and the wrong hash. Fix: require `fwrite() === strlen($line)` and a true `fclose()`, otherwise throw `ExportGenerateException`.
- `app/Support/ExportDownload.php:36`: a HEAD request in stream mode reads the whole file and logs `bytes_sent_by_php` = file size. Fix: skip streaming and log 0 bytes when `$request->isMethod('HEAD')`.
- `app/Support/ExportDownloadLog.php:58` (also `ServeExportController.php:19`): the raw `X-Bench-Run` header and `SERVER_SOFTWARE` go into `json_encode(JSON_THROW_ON_ERROR)` inside a shutdown callback. Invalid UTF-8 makes it throw, and the log line is lost. A client can also forge `bench_run` values and skew bench aggregation. Fix: validate `X-Bench-Run` (`^[a-z0-9-]{1,64}$`) in `ServeExportRequest`, and use `JSON_INVALID_UTF8_SUBSTITUTE` or catch `JsonException`.
- `app/Console/Commands/ExportsGenerateCommand.php:37`: a tiny or huge `--target-mb` produces a header-only export with `rows=0` and returns success. Fix: require at least one data row's worth of bytes and cap the value.
- `config/exports.php:60`: the `frankenphp`/`caddy` → `x-sendfile` mapping also applies on the `frankenphp-worker` and `frankenphp-octane` servers, which have no `intercept`. The result is an empty 50 MiB response that leaks the absolute path in `X-Sendfile`. Fix: turn on x-sendfile only per server or by env opt-in, or exclude worker and Octane SAPIs so they fall back to `stream-fallback`.
- `app/Support/ExportStreamer.php:22`: a client can pick `mode=stream`, and `set_time_limit(0)` lets a slow reader hold an FPM child indefinitely. Fix: set a bounded wall-clock limit (for example `max(60, bytes / min_rate)`), and optionally cap concurrent streams.
- `app/DTOs/ExportDelivery.php:18`: `$mode` is never read, and `label` is a free string that repeats the header null-check. Fix: drop `mode` and make `label` a `DeliveryMode` enum (`Offload`/`StreamFallback`/`Stream`).
