# Ship report: spec-20261030-1437-octane-worker-mode

## Summary

This slice adds FrankenPHP worker mode, built two ways, as switchable DDEV servers. `frankenphp-octane` runs Laravel Octane's `octane:frankenphp` daemon. `frankenphp-worker` uses the DDEV add-on's Caddyfile with one `worker` pool that runs `public/frankenphp-worker.php`. The live walk worked on both servers: 4 worker threads each, sapi `frankenphp`, opcache on, parity identical with nginx-fpm, and a versions row for each. The other four servers did not change, and `.ddev/config.yaml` was never touched. The suite and static gates are green.

It is not ready to ship:

- Build is 9/12. Converge round-2 tasks 10-12 were not built.
- AC-9 fails. The README gets the flush timing wrong, leaves out the FrankenPHP `max_requests` note, and claims `octane:reload` works on frankenphp-worker. The live check shows it does not.
- AC-6 fails because the parity snapshots are not committed.
- Review confirmed 5 major findings after duplicates were merged, including an unscoped `trustProxies(at: '*')`.
- All new files are still untracked.

## Confirmed review findings

Duplicates reported under more than one dimension are merged.

### Major

- `bootstrap/app.php:22`: `trustProxies(at: '*')` applies to all six servers in every environment. Any client can then spoof X-Forwarded-For, -Host, -Proto and -Port, which affects `ip()`, generated URLs and `isSecure()`. It is also an app-code change the spec listed under "Ask first", and there is no record of approval. **Fix:** trust only private CIDRs or a `TRUSTED_PROXIES` env value that defaults to off, limit trust to the forwarded proto/port headers, and get explicit approval. Or fix the scheme in the worker Caddyfile instead.
- `README.md:128` and `README.md:135`: the README says `octane:reload` "also works" on frankenphp-worker "without the Octane daemon". It only works because of a leftover state file, and it fails on a fresh clone. **Fix:** name only `ddev restart` (or a direct admin-API call) for frankenphp-worker, matching `bench/versions.sh:26`.
- `.ddev/servers/frankenphp-octane/config.frankenphp-octane.yaml:4`: `--log-level=info` makes Octane's stub Caddyfile write a JSON access-log line for every request, and a polling PHP parent re-echoes each line. frankenphp-worker writes no access log, so the two do different work under SL-08 load. **Fix:** use `--log-level=warn`, or add the same `log` block to the worker Caddyfile, then correct the README log row.

### Minor

- `.ddev/servers/frankenphp-worker/web-build/Caddyfile.frankenphp:52-59`: the worker block does not set `REQUEST_MAX_EXECUTION_TIME`, so frankenphp-worker has no per-request limit while frankenphp-octane has 30 s. **Fix:** add `env REQUEST_MAX_EXECUTION_TIME 30` and list it in CHANGES.md.
- `README.md:118`: the README says `flush` services are dropped "before every request"; they are flushed after it, on OperationTerminated. The FrankenPHP `max_requests` note is also missing. **Fix:** build task 10.
- `README.md:116`: the README says `--max-requests` falls back to `max_requests` in `config/octane.php`. No such key exists; the default is the option's literal 500. **Fix:** drop the claim.
- `public/frankenphp-worker.php:3`: `LARAVEL_START` is defined once per worker boot, so `/up` shows worker uptime instead of render time. **Fix:** remove the line (go back to the Octane stub) or measure per request. Also correct `BENCHMARKS.md:30`.
- `config/octane.php:41`: the default is still `'roadrunner'`, so `octane:reload` breaks on a `.env` that predates this change. **Fix:** default to `'frankenphp'`, or pass `--server=frankenphp` in the documented commands.
- `tests/Feature/OctaneInstallTest.php:27`: the trust-proxy and `LARAVEL_START` tests are labelled AC-6, which is the parity criterion. **Fix:** relabel them, or add a spec decision and an AC for proxy trust.
