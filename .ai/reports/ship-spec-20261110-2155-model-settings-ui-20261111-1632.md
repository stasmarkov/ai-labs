# Ship report: spec-20261110-2155-model-settings-ui

Date: 2026-11-11 16:32

## Summary

This is the local-only model settings page (`/ai/settings`). A learner picks a provider and model per AI feature, the choice is stored in `ai_settings`, and the resolver applies it in this order: request, then settings, then configuration, then default. Most of it works, and all gates are green: Pint, PHPStan, 1815 PHPUnit tests and the debug scan.

The original scenario still fails end to end. After a save, the next request that reads the setting from Redis gets a `__PHP_Incomplete_Class`, and every page answers 500. That includes `/`, `/ai`, `/ai/settings` and the describe endpoint. The tests miss it because they use the array cache store. Four spec tasks are still open (10, 13, 14, 15).

**Recommendation: BLOCKED.**

## Confirmed review findings

### Critical

- `app/Repositories/EloquentAiSettingsRepository.php:34`: cached `AiSettingChoice` objects come back as `__PHP_Incomplete_Class`, so every request fails once a setting is saved. **Fix:** cache plain arrays (`toArray()`) and rebuild the DTOs after reading, or allow-list the DTO in `cache.serializable_classes`. Add a test that uses a serializing store.

### Major

- `app/Services/AiSettingsService.php:79`: untagged Ollama ids such as `bge-m3` never match the `/api/tags` names (`bge-m3:latest`). The page shows a false "not installed", the configured model can't be saved, and a re-index is forced. **Fix:** treat `x` and `x:latest` as the same model when checking installation, validating and comparing.
- `app/Services/AiSettingsService.php:73`: `OllamaServerInfo::models()` is called about 21 times per page load, which is about 21×(N+1) Redis round-trips. **Fix:** build the model list once per `rows()` call (or memoize it), and only when the driver is ollama.
- `app/Ai/OllamaServerInfo.php:133`: failed `/api/show` lookups are never cached, so they are re-POSTed on every `models()` call, up to 3 s each. **Fix:** cache the guessed result for a short TTL (for example 10 s) and memoize per request.

### Minor

- `app/Services/AiSettingsService.php:244`: when Ollama is unreachable, the fallback list accepts cloud model ids, and the text default for photo-vision. **Fix:** include the configured or saved model only when its provider is ollama.
- `app/Ai/AiProviders.php:263`: the row source says `configuration` when only the model is configured and the provider comes from `ai.default`. **Fix:** set the source from the provider's level (`default`) and keep `modelSource=configuration`. Update the MNC-1 test.
- `app/Ai/OllamaServerInfo.php:135`: if `/api/show` fails, or no models can be classified, photo-vision (or every row) gets an empty list that can't be saved, and the note is wrong. **Fix:** fall back to the unreachable path with configured ids and a correct note, and flag "not installed" even when the list is empty.
- `app/Ai/AiProviders.php:272`: model ids read from the database are trusted and put into the copyable `ollama pull …` command (`AiSettingsService.php:81`, `LabSettingRow.vue:119`). **Fix:** drop saved models that don't match `OTHER_MODEL_PATTERN`, or `escapeshellarg()` the model in the command.
- `app/Services/AiSettingsService.php:20`: `OTHER_MODEL_PATTERN` allows `..` segments, and the Gemini embeddings URL path is built from the model id. **Fix:** use `/^(?!.*\.\.)[A-Za-z0-9][A-Za-z0-9._:\/-]{0,119}$/` and add a test case.
- `app/Ai/OllamaServerInfo.php:104`: the cloud `available()` model lists live on `OllamaServerInfo`. **Fix:** move `available()` to `AiProviders` and move its test with it.
- `app/Services/AiSettingsService.php:71`: `installation()` fetches the Ollama models before checking the driver, so fake and cloud rows pay for the lookup too. **Fix:** check the driver first. This is the same fix as the major `models()` finding.
