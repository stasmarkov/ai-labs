# Ship report: prompt playground with versions (SL-43)

## Summary

The prompt playground mostly works. You can save prompts as numbered immutable versions, run one input against 2 or 3 models side by side, reopen stored runs, diff versions, and read the six-tab guide. All gates pass: Pint, PHPStan, the full suite (2850 passed, 3 skipped) and the debug scan.

It is not ready to ship, for four reasons:

- The build is partial. Tasks 2, 3 and 5 were reported incomplete.
- Two converge gaps (9 and 10) were not built.
- AC-3 (BR-90) fails live when a prompt name is long.
- The review confirmed four major findings, two of them security issues on public deploys.

All the playground code is still uncommitted on `master`.

**Broken hop: AC-3 (BR-90).** The run label is `playground:<name>@vN`. Names may be up to 80 characters (`app/Services/PlaygroundPromptService.php:36`), so the label can reach 94 characters, but `ai_runs.prompt_version` is `varchar(80)`. `AiRunRecorder::recordRun` wraps the insert in `rescue()`, so the insert fails without an error. The run still returns 200, but no `ai_runs` row is written and the result's "Run log" link returns 404. Reproduced with an 80-character name: label length 94, 0 rows, and 404 on both `/ai/runs/01a1dbd1-9958-71bf-8fe3-6a9f07da4c99` and `/ai/runs/01a1dbd1-9967-7371-b649-b72f2169522f`. The failure starts at names of about 66 characters (for v1 to v9).

## Confirmed review findings

### Major

- `app/Services/PlaygroundRunner.php:203`: anonymous visitors can run any cloud model ID that matches the pattern, which makes the operator's key an open LLM proxy. Fix: outside local, accept only `[default, ...available()]`, and allow the free pattern only when `EnsureLocalLab::available()`.
- `app/Repositories/EloquentPlaygroundRunRepository.php:67`: every anonymous run is stored with its input, system prompt and outputs, then listed to all visitors with wildcard CORS and no pruning. Fix: outside local, either skip persisting runs or scope history to the requester, and add retention.
- `app/Http/Middleware/LimitCloudAi.php:30`: the middleware resolves the whole `PlaygroundRunner` graph on all 10 AI routes just to call `cloudTargetCount()`. Fix: move the local/cloud count into `AiProviders` and call it from both places.
- `app/Services/PlaygroundPromptService.php:50`: the version-field rules (length, temperature, max_tokens) are enforced only in the FormRequest, so a direct service call can store an empty prompt or hit the CHECK constraint and return 500. Fix: enforce them in the service or in the `NewPlaygroundVersion` DTO.

### Minor

- `app/DTOs/NewPlaygroundVersion.php:29` and `database/migrations/2026_11_14_200100_create_playground_prompt_versions_table.php:22`: temperature is stored as `decimal(3,2)` but validated and sent unrounded. A value like 0.201 slips past the `unchanged` check, and a reopened run shows a temperature that was never sent. Fix: round to 2 decimals in the DTO and in `resolveSource`, or validate with `decimal:0,2`.
- `app/Services/PlaygroundTargetCatalog.php:68`: `defaultTargets()` is not capped at `MAX_TARGETS`, so 4 or more configured defaults make every first run fail with 422. Fix: stop adding targets at `PlaygroundRunner::MAX_TARGETS`.
- `config/ai.php:316`: `target_timeout` has a floor but no ceiling, so 3 slow targets can outlast the 200 s request limit and the run is lost. Fix: clamp the value with `min(60, ...)`, or derive the request limit from `3 * target_timeout + margin`.
- `resources/js/ai/Pages/Lab/Playground.vue:196`: every 404 is shown as "Saving prompts is available on a local machine". Fix: show that message only when `!props.canSave`, and handle the `not_found` code separately.
- `app/Services/PlaygroundRunner.php:293`: `redact()` leaves hostnames, ports and provider response bodies in public error text. Fix: store a generic message per failure class and keep the detail only in `report()`.
- `app/Repositories/EloquentPlaygroundRunRepository.php:69`: `recent()` runs `SELECT *`, which loads up to 50 full prompts and inputs per page render. Fix: select `id`, `version_label`, `created_at` and `left(input, 80)`.

## Recommendation

**FIX-FIRST**

The build is partial (tasks 2, 3 and 5), converge gaps 9 and 10 are unbuilt, and AC-3 fails live. Four major findings are open, two of them about how public deploys handle cloud keys and stored runs. The feature is also still uncommitted.

Next: cap prompt names so `playground:<name>@vN` fits `ai_runs.prompt_version` varchar(80) (a limit of 60 in `app/Services/PlaygroundPromptService.php:36` and in the request rule), or widen that column. Then add a `PlaygroundRunTest` case at the maximum name length that asserts the `ai_runs` rows exist and the run-log links resolve.
