## Confirmed review findings

Two reports said the same thing (reasoning deltas skip the output guard): one rated it a major security issue, the other a minor correctness issue. They are merged below at major.

### Major

- **`app/Ai/CitationParser.php:19`**: the lookbehind `(?<![\w\]`])` drops the second marker in `[2][3]`, which is the form `resources/prompts/docs-answer.v1.md:5` tells the model to use. `parse('Limits apply [2][3]. Also [1].', 6)` returns `used=[2,1]`, so source 3 is missing from `citations` and `cited_chunk_ids` while Chat.vue still links it. **Fix:** change the prompt example to `[2, 3]`, and add a test that parses every example in the prompt (this is task 14).
- **`app/Ai/DocsAnswerProtocol.php:54`**: only `TextDelta` is added to the guarded text. `ReasoningDelta` events are forwarded unchecked at line 78. With `AI_THINK=true`, the model's thinking can restate the system prompt or the canary, which breaks AC-5 and NFR-2. **Fix:** add reasoning deltas to the guarded text, or drop reasoning events in this protocol, and add a test for the reasoning case.

### Minor

- **`resources/guards/prompt-injection.v1.php:11`**: `ignore-previous` accepts `all`/`rules` with 40 characters of anything in between. It refuses questions like "How do I override all the default validation rules?", and `reveal-prompt` (line 12) refuses "show a system message to users…". **Fix:** narrow both patterns, and add these questions to the benign dataset.
- **`app/Ai/OutputGuard.php:61`**: the word split keeps `[n]` digits as words, so interleaved citations break the 12-word overlap match. The spec says markers are not words. **Fix:** remove `\[\d+(?:\s*,\s*\d+)*\]` before splitting.
- **`app/Services/DocsAnswerContext.php:53`**: any chunk with a full-text rank passes the gate, but `websearch_to_tsquery` (`EloquentDocsSearchRepository.php:50`) turns `or` into OR and a leading `-` into negation. So "world cup or the final" passes on one word, and the model is called instead of returning `no_context` (AC-3). **Fix:** require a high enough similarity even with a text hit, or use `plainto_tsquery` for the gate.
- **`app/Services/DocsAnswerService.php:46`** (and line 62): the invocation id returned by `recordOutcome()` is discarded, so refused and no_context runs never show their logged run on `/ai/chat` (AC-10). **Fix:** add `invocation_id` to the `refused` and `no_context` event payloads, and load the run from it in Chat.vue.
- **`routes/catalog.php:27`**: the GET query string puts the question into access logs, browser history and Referer. Cross-site pages can also start model runs that count against the visitor's IP. **Fix:** switch to POST with a JSON body (the client already uses `fetch()`), with CSRF or same-origin checks.
