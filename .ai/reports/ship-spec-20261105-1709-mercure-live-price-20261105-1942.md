## Confirmed review findings

### Major

- `app/Listeners/PublishListingPrice.php:17`: the hub publish is a synchronous HTTP call inside every Listing update (2 s timeout, 1 s connect). Also, `MERCURE_ENABLED` defaults to true (`config/mercure.php:17`), so the five servers with no hub POST to themselves and boot Laravel to answer 404. Fix: implement `ShouldQueue` and default `MERCURE_ENABLED` to false unless a hub is present.
- `app/Models/Listing.php:35`: the domain event is raised from an Eloquent `updated` hook, and the DTO is built a second time in `EloquentListingRepository::updatePrice` (lines 25-31). Fix: dispatch the event once, from the repository or service using the DTO it returns, and remove the model hook.

### Minor

- `resources/js/app.js:13`: a price change between render and EventSource connect, or during a reconnect, is lost, because `transport local` keeps no history. Fix: use the bolt transport with a short history plus `lastEventID`, or refetch the price on `onopen`.
- `app/Http/Controllers/ShowListingController.php:25`: the same-origin `mercureAuthorization` cookie goes with every public subscription. A stale or rotated JWT gets a 401 and live prices stop on all listings. The cookie expiry also comes from a second `time()` call, and the guide at `docs/learning-guide.md:1049` wrongly credits `withCredentials`. Fix: give each subscription its own cookie path or name, or drop the cookie when no private watch is active. Take expiry from the JWT's `exp`, and correct the guide.
- `app/Support/MercureTokens.php:42`: `iat` and `exp` come from two `time()` calls, so the lifetime can be ttl+1 and the tests can fail now and then. Fix: read `$now = time()` once.
- `app/Console/Commands/ListingsRepriceCommand.php:46`: when the public publish fails, the command prints nothing; only a private failure gets a warning. The listener drops the bool at `PublishListingPrice.php:17`. Fix: show the public publish result in the command.
- `.ddev/servers/frankenphp/web-build/Caddyfile.frankenphp:14`: `servers { metrics }` adds per-request work to every frankenphp benchmark, and BENCHMARKS.md does not record it. Fix: record the change as a difference between cells, or turn metrics on only during `mercure-load.sh` runs.
- `app/Console/Commands/MercureKeysCommand.php:82`: the secret files are written with the default umask, usually 0644. Fix: `chmod($file, 0600)`, or write a 0600 temp file and rename it.
- `resources/js/app.js:13`: on the five servers with no hub, every detail-page view sends one extra request that boots PHP. Fix: render the hub meta tag and topic only when a hub is configured.
- `BENCHMARKS.md:924` (and `:919`): wrong cause given for the busy thread (the reprice CLI is not in the FrankenPHP pool) and for the latency tail (the local transport does not write to subscribers one by one). Fix: name the /healthz probe, the Node subscriber loop, the router hop and CPU contention as the likely causes.
- `app/Console/Commands/MercureTokenCommand.php:24`: `--private` is a required option. Fix: drop the flag, or rename the command to `mercure:private-token`.
- `app/Support/MercurePublisher.php:24`: `json_encode(..., JSON_THROW_ON_ERROR)` runs outside the try, and `JsonException` is not caught, which breaks the never-throws contract (MNC-4). Fix: move the encoding into the try and catch `JsonException`.
