Results:

- Replay: no new `ai_runs` row, and the JSON report is byte-equal to the stored one.
- Refusals: exit 3, with no model call.
- Unknown replay id: "No research run with this id.", exit 2.
- API: 422, 415, 403, 200-refused and 202 all as expected, then running moved to done, and 404 for unknown ids.

No hop in the journey broke. The step checks that failed:

- **Recent runs list (cosmetic):** a finished run still shows as `running` until the page is reloaded, because the list is a static prop.
- **README exit codes are wrong:** it says "1 failed or refused (or an unknown replay id)". The code returns 3 for refused and 2 for an unknown replay id, as C-8 requires.
- **Operability:** the page flow needs `ddev artisan queue:work`, because `QUEUE_CONNECTION=database` and DDEV starts no worker. The README research section does not say so. Without a worker, a page run stays `running` and later shows as stale or failed.

Other caveats:

- The physical Redis key carries the connection prefix (`ai-lab-database-research:run:{id}:notes`), while C-7 says the prefix is empty. The logical key matches AC-5.
- C-11 (the Numbers tab) is not met.
- One `--filter=Docs` run exited 2 while live work was running at the same time. Three reruns passed with 307 tests each, so it did not reproduce.

**E2E regression test:** none was written. The stack is Laravel only, with no frontend e2e config, and the E2E stage returned null. No AC ids are traced to an e2e test, so the browser journey is covered only by the manual Playwright run.

## Confirmed review findings

Two findings were reported twice by different reviewers and are merged below (the job timeout, and the model being resolved again on each call).

### Major

1. `app/Services/ResearchRunService.php:24` (security): the `MARKDOWN` options still allow markdown images and external `http(s)` links in the model-written report. That report is rendered with `v-html` on public run pages that are listed under "recent", which allows tracking pixels and phishing links. **Fix:** turn off images, allow only `#research-source-n` links (or add `rel="nofollow noopener"` plus a host allow-list), and add tests for `![x](https://…)` and for external links.
2. `app/Console/Commands/AgentResearchCommand.php:66`: `--replay=abc` (any id that is not a UUID) throws a PostgreSQL `22P02` QueryException and exits 1. **Fix:** check `Str::isUuid()` before the lookup, then print "No research run with this id." and exit 2.
3. `resources/js/ai/Pages/Lab/Research.vue:226`: clicking Replay during a running run calls `stopTimers()` and never starts polling again, so the page stays on "Working…" for good. **Fix:** disable Replay while polling, or call `schedulePoll()` when the replay ends.
4. `app/Jobs/ExecuteResearchRunJob.php:29`: the 300 s job timeout is shorter than the worst case of 8 sequential calls at 120 s each, plus the embeddings. The job is killed and the run ends as `job_failed`. **Fix:** check a wall-clock deadline in `ResearchRunner::call()` and stop with `cap_reached` before the job timeout, set short per-call timeouts, and consider running the note searches concurrently.
5. `app/Services/ResearchRunner.php:552-554`: `agent()` pins only the provider, so the model is resolved again from settings on every call. The model actually called can then differ from `research_runs.model`, which breaks the AC-7 rule that all three agents use the same model. **Fix:** pin the stored provider and model on each agent.

### Minor

- `app/Services/ResearchRunner.php:275`: a failed search is stored as a skipped `no_sources` note, so a run can end `done` with a false "not covered" report. **Fix:** use a separate `search_failed` reason, and do not count skipped or failed notes as usable when choosing between not covered and failed.
- `app/Services/ResearchRunService.php:130`: the citation linker rewrites `[1]` inside code and never links `[1, 2]`. **Fix:** reuse the `ResearchCitations`/`CitationParser` marker regex and the fenced-code split.
- `app/Services/ResearchRunner.php:115`: a run already shown as stale/failed can still run later. **Fix:** in `execute()`, refuse runs older than `STALE_AFTER_MINUTES` and finish them as failed/stale.
- `app/Services/ResearchRunner.php:530`: invalid plan and note outputs are recorded in `ai_runs` as plain `completed`. **Fix:** pass `validationFailed: true`, as the other structured-output features do.
- `routes/catalog.php:70`: `LimitCloudAi` counts 1 hit per run, but a run makes up to 8 cloud calls. **Fix:** weight the hit by `max_model_calls`, or count inside `ResearchRunner::call`.
- `routes/catalog.php:72`: the GET run endpoints (API and `/ai/research/{id}`) have no rate limit, although the spec says they do. **Fix:** add a generous `research-show` limiter.
- `app/Services/ResearchRunner.php:130` (and `:273`): raw exception messages, such as SQL or internal host names, are stored and served through the public GET. **Fix:** store stable error codes and keep the full messages in the logs only.
- `app/Jobs/ExecuteResearchRunJob.php:43`: `failed()` resets the run's counts and sources to 0. **Fix:** finish the run through the runner or service, and keep or recompute the stored counts.
- `app/Services/LabOverviewService.php:115`: the guide-gating code for `RESEARCH_PAGE` and `navigationPages()` is now dead. **Fix:** add `RESEARCH_PAGE` to `self::PAGES` and remove that code.
- `app/Support/ArrayResearchNotesStore.php:10`: a store used only by tests ships in `app/`, and its docblock is misleading. **Fix:** move it to `tests/`, or wire a real switch for it.
- `app/Services/ResearchRunner.php:115`: run and step statuses and phases are raw strings spread across the layers. **Fix:** add backed enums in `app/Enums` and cast them on the models.
