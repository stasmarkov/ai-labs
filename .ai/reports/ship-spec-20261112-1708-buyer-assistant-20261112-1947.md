# Ship report: buyer assistant with a SearchListings tool (SL-25)

## Summary

The buyer assistant works for a user on the live DDEV site. A question on `/ai/assistant` reaches the `SearchListings` tool, the tool validates the arguments with `ListingFilterRules` and runs the existing search, the answer streams over SSE, and the step timeline shows status, arguments, summary and `/listings/{id}` links. All four quality gates pass (2186 tests).

It is not ready to ship:

- The build is partial. Task 7 (live eval, fingerprint, parity) is open, and the four converge round-2 gap tasks (14 to 17) were not built.
- Acceptance is not resolved. In the dev database the two new migrations are pending. `EloquentAiRunRepository::save` now always writes `tool_steps`/`tool_errors`, so every `ai_runs` insert fails with SQLSTATE 42703. No assistant turn is logged, the "Logged run" link returns 404, and chat and refusal runs from other features are not logged either.
- Review confirmed two major findings. An empty-string `fuel` argument crashes the whole turn. The `ReadOnlyTool` marker does not enforce AC-6.
- All the work is uncommitted (26 tracked files changed, 78 entries in `git status`).

## Confirmed review findings

### Major

- `app/Ai/Tools/SearchListings.php:93`: `{"fuel":""}` passes `ListingFilterRules` and reaches `Fuel::from('')`, which throws a `ValueError`. The SDK rethrows it and the whole turn fails. Blank `make`, `model` and `city` values silently return 0 listings. Fix: trim strings and turn `''` into null before validating, or drop blank values in the `array_filter`.
- `app/Ai/Tools/ReadOnlyTool.php:13`: `ReadOnlyTool` is an empty marker interface, so a tool that writes can implement it and still pass the AC-6 test. `docs/learning-guide.md:1291` wrongly says the tool list is typed. Fix: assert `instanceof ReadOnlyTool` at runtime in `tools()` (or use an allowlist, or a test that runs the tool in a transaction and asserts no writes), and correct the guide wording.

### Minor

- `app/Services/AssistantEvalScorer.php:183`: `str_contains` matching makes `unsupported_mentioned` almost always true ("red" in "offered", "euro" in "euros"). Fix: match on word boundaries with `preg_match('/\b…\b/u')` and drop `euro` from the as-17 label.
- `app/Services/AssistantEvalScorer.php:17`: `ID_PATTERN` counts `#N` and `id N` as listing ids, so ranking numbers ("#1 pick") are reported as hallucinations. Fix: restrict detection to `/listings/N` and `listing N`, or store the answer text in `run.json`.
- `resources/prompts/buyer-assistant.v2.md:8`: the prompt omits the clarity gate 1 rules on distance ("near"), other currencies and sorting, and both models silently treated 12000 dollars as 12000 euros. Fix: write prompt v3 (task 16) and add `max_price` handling to the as-17 label.
- `BENCHMARKS.md:15`: the published table and `bench/results/assistant/2026-11-12/run.json` lack `unsupported_mentioned`. Fix: re-run `assistant:eval` on the current code (task 7) and add the column.
- `app/Ai/Tools/SearchListings.php:74`: the tool emits the codes `invalid` and `call_limit`, but the spec contract says `invalid_arguments` and `step_limit`. `AssistantEvalRunner` hard-codes `invalid`. Fix: align the codes across the tool, the step log, SSE and the eval (task 14), or amend the spec.
- `.env.example:109`: it says `AI_PROMPT_BUYER_ASSISTANT=buyer-assistant.v1`, but `config/ai.php` defaults to v2. `docs/learning-guide.md:1293` describes the old id pattern, and `run.json` is stale. Fix: update the default to v2 (v3 after task 16), refresh the guide paragraph and re-run the eval.
- `app/Ai/Tools/SearchListings.php:62`: the fuel list is hard-coded in the schema and in `description()` (line 47). Fix: use `array_column(Fuel::cases(), 'value')`, as `ListingFilterAgent.php:41` does.
- `resources/prompts/buyer-assistant.v2.md:1`: the prompts name the tool `search_listings`, but the SDK exposes it as `SearchListings`, and `BuyerAssistantAgentTest.php:77` pins the wrong name. Fix: add `name(): string { return 'search_listings'; }` to the tool, or fix the prompts and the test.
- `app/Services/BuyerAssistantService.php:39`: the input guard over the history and the `input:<guard>:<pattern><suffix>` reason format duplicate `DocsAnswerService.php:183-205`. Fix: move both into one shared helper (for example on `PromptInjectionGuard`).
