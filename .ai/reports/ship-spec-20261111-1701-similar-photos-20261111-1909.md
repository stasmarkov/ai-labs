# Ship report: spec-20261111-1701-similar-photos (SL-36, similar car photos)

## Summary

SL-36 adds similar car photos backed by a local CLIP encoder sidecar (Infinity, `openai/clip-vit-base-patch32`). Vectors live in pgvector, matches are cached in Redis, and the results show on `/ai/photos` and as a "Similar cars" block on the listing page. The eval command, the guide, the settings row and the BENCHMARKS section are in. All gates pass and the main journey works live end to end. The build is still incomplete (15/18): converge left two gaps unbuilt, and AC-7 (with part of AC-4) fails because a cached result outlives a label switch back. Review also found one major correctness issue: `photos:embed --wait` hangs when a batch fails with anything other than a `PhotoEncoderException`.

## Confirmed review findings

### Major

- `app/Services/PhotoEmbeddingService.php:140`: `embedBatch()` catches only `PhotoEncoderException`, so any other failure never settles the counters and `photos:embed --wait` polls for 30 min. Fix: settle the counters in `finally` (or in a job `failed()` hook) and record a failed `ai_runs` row on any `Throwable`.
- `app/Repositories/EloquentSimilarEvalRepository.php:40`: the repository re-parses the service's invocation-id format with a hardcoded UUID length of 36. Fix: pass the run prefix in from the service, or store `run_id` in its own column. (This is also why gap 10's throughput fix is fragile.)

### Minor

- `app/Services/SimilarPhotosService.php:35`: a cache hit ignores the stored label after a switch back (AC-7, gap 17). Fix: check the photo's `embedding_model` before returning the cached value, or bump every label's generation on `--fresh`.
- `app/Services/SimilarPhotosService.php:77`: the cache key leaves out `min_score`, the cutoff and the limit. Fix: put the thresholds in the key, or bump the generation when they change.
- `app/Ai/PhotoEncoderClient.php:104`: response indices are not validated. Fix: require the sorted indices to be exactly 0..n-1.
- `app/Services/PhotoEmbeddingService.php:65`: a non-encoder provider gives a "0 dimensions" error. Fix: check the driver before the dimensions.
- `resources/views/listings/show.blade.php:26`: "Similar cars" sits after the dealer section; the spec puts it under the hero image. Fix: move the block under the hero and add an assertion.
- `.ddev/docker-compose.photo-encoder.yaml:19`: the HF models are unpinned and Infinity trusts remote code by default. Fix: add `--no-trust-remote-code` and `--revision <sha>` per model, and assert both in `PhotoEncoderComposeTest`.
- `app/Services/SimilarEvalService.php:52`: the same HNSW search runs 9 times per photo. Fix: fetch the candidates once, then filter per threshold.
- `app/Repositories/EloquentPhotoLabRepository.php:22`: `SELECT *` pulls the 512-dim `embedding` on every lab page. Fix: select `id, listing_id, path` and add `embedding` to `$hidden`.
- `app/Services/SimilarPhotosService.php:55`: the `min_score` fallback 0.80 is repeated in three places and conflicts with the 0.75 config default. Fix: read it in one accessor and drop the inline fallbacks.
- `app/Repositories/EloquentListingPhotoRepository.php:83`: `embeddingCount` runs `Schema::hasColumn` plus 3 queries. Fix: copy the sibling single query with `FILTER`.
- `app/Http/Controllers/ShowListingController.php:35`: the failure policy sits in the controller, and the lab page has no guard. Fix: move the degrade-on-failure handling into the service.
- `resources/views/listings/show.blade.php:33`: photo URLs are built inconsistently (`asset()` here, relative `Storage::url` path elsewhere, a copied helper in `PhotoLabService:87`). Fix: one shared helper, or have the repository return the URL.
