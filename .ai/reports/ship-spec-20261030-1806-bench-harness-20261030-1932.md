# Ship report: spec-20261030-1806-bench-harness

## Summary

This slice builds the benchmark harness:

- `bench/run.sh` handles run conditions, the traffic path, warm-up/measure/repeat, memory and CPU sampling, and the automatic rerun set.
- `bench/suite.sh` drives the fair/sweep/tuned matrix. `bench/summary.php` produces the median, spread, ratio and summary JSON.
- `bench/concurrency.sh` and `bench/timeouts.sh` handle concurrency and timeouts. `bench/pick-tuned.sh` picks the tuned setting, and `bench/k6-search.js` drives the search scenario.
- `/debug/sleep/{seconds}` is new, `/debug/runtime` now has an Xdebug field, and BENCHMARKS.md has an Expectations section (committed in 8e38d62) plus a "How the numbers work" section.

The tests and static gates pass: 223 tests and 1135 assertions.

It is not ready to ship:

- Converge round 2 left 4 gaps unbuilt (16-19). Two of them are live defects: the nginx timeout overlay has no effect, and the sampler takes idle samples.
- Acceptance does not resolve end to end. AC-5, AC-6, AC-7, AC-9, AC-10 (Surprises), AC-12 and MNC-2 are not met.
- Review confirmed 1 critical finding: `suite.sh` dies on the host's bash 3.2. There are also 7 major findings after duplicates were merged.

## Confirmed review findings

Duplicates from several review dimensions are merged below.

### Critical

- `bench/suite.sh:55` (also :47 for `baseline_args`, and `raw_files`): under `set -u`, bash 3.2 (the only bash on the host) treats an empty `"${arr[@]}"` as an unbound variable. The suite therefore dies on the first fair run, or at the first summary with `--quick`. **Fix:** use `${arr[@]+"${arr[@]}"}`, or require bash >= 4.4 and fail fast.

### Major

- `app/Http/Controllers/DebugSleepController.php:17` and `routes/debug.php:8`: `whereNumber` lets `99999999999999999999` through. Binding it to the `int` parameter throws a TypeError before the `DEBUG_ROUTES` guard runs.
  - Effect: with the flag off it returns 500 instead of 404, which reveals the route and lets anyone write error-level log entries at will. With the flag on it returns 500 instead of 422.
  - **Fix:** constrain the route with `->where('seconds', '[0-9]{1,3}')`, or take a `string` and check the guard first. Also register `routes/debug.php` only when the flag is on.
- `bench/suite.sh:40`: `write_summary` computes `date` again, separately from run.sh's `DATE`. A run that crosses midnight UTC finds no raw files (summary exits 2 and the suite aborts), or hits a missing baseline (JsonException). **Fix:** compute the date once at suite start and pass it to run.sh and the summary.
- `bench/run.sh:134`: the router IP is read before run.sh's own `ddev restart` (:232). The router can come back with a new IP, which sends load to a stale address or around the router. **Fix:** read the IP, and recheck the run conditions, after the restart, right before warm-up.
- `bench/timeouts.sh:139`: `classify()` reads the last 40 log lines. These include the entrypoint xtrace (`request_terminate_timeout = 10s`) and log lines from earlier requests, so requests can be credited to the wrong layer. **Fix:** use `ddev logs --since <request start>` and match `execution timed out` instead of the directive name.
- `bench/timeouts.sh:71`: the server-level `fastcgi_read_timeout 10s` is overridden by the location-level `10m`, so the nginx layer is never shortened, although the header comment at :7 claims it is (gap 16). **Fix:** rewrite the location-level value, or set it inside the PHP location.
- `bench/run.sh:165` (also :171, :180, :200): one `docker stats --no-stream` call plus `sleep 1` gives a sample every 2-3 s, and the samples taken before and after the window are averaged in.
  - Effect: CPU is understated by roughly 8-30 %, depending on run length (gap 17).
  - **Fix:** sample only while the generator runs, drop the bookend samples from the CPU average, and remove the extra sleep.
- `bench/run.sh:268` and `bench/summary.php:39`, `:50`, `:246`: the spread/rerun rule is implemented twice, and the 5 % limit is defined in three places. summary.php's `rerun_needed` and exit 3 can never matter, because run.sh has already rerun and suite.sh ignores exit 3. **Fix:** keep the rule in one place and remove the dead path.

### Minor

- `bench/run.sh:159`: if the k6 measure run fails, the `cat` reads the k6.json left by the warm-up, so warm-up metrics are recorded as the measurement with exit 0. **Fix:** delete `k6.json` before each run and check the docker exit status.
- `bench/run.sh:157`: oha `-z` without `-w` counts requests aborted at the deadline as errors. That can add up to 50 false errors per run and skew the 1 % sweep cut-off. **Fix:** pass `-w`, or exclude that error key.
- `bench/run.sh:248`: `--label` is put into output paths without validation, so a label with `/` or `..` writes outside the results folder. **Fix:** validate it against `^[A-Za-z0-9._-]+$`.
- `bench/summary.php:68` and `:73`: directory mode merges all scenarios, labels and servers into one median, although the docblock promises one row per group. **Fix:** group by server, scenario, label and concurrency, or reject mixed input.
- `bench/summary.php:176`: `benchMemory()` is called only from a test. Nothing builds the AC-7 memory table. **Fix:** wire it into the suite or remove it.
- `tests/Unit/ArchTest.php:10`: the "thin final invokable controllers" rule lists three controllers and leaves out the debug controllers. **Fix:** target the `App\Http\Controllers` namespace instead.
- `bench/concurrency.sh:91` and `bench/timeouts.sh:124`: the worker-mode branches are out of scope (SL-08) and untested. For octane, the `num_threads` overlay probably has no effect, yet it would still be recorded. **Fix:** remove the branches or make them refuse.
- `.ai/specs/spec-20261030-1806-bench-harness/tasks.md:62` and `:69`: the traceability rows for AC-8 and MNC-3 name tests that do not exist. **Fix:** use the real test names.
- `.ai/specs/spec-20261030-1806-bench-harness/tasks.md:28` and `spec-lite.md:115`: these say "committed overlays", but the overlays are gitignored, as the clean-tree check requires. **Fix:** update the wording.
