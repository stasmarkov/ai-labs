## Confirmed review findings

Duplicate findings are merged below.

### Major

- `routes/web.php:32`: a `provider` value in the request body makes `LimitCloudAi` skip the cloud limits, the global budget and the Sec-Fetch-Site guard. The job still runs on the configured, possibly paid, provider. **Fix:** make `LimitCloudAi` ignore the override for `photo-vision`, or have the controller honour or reject `provider` the same way the middleware does.
- `config/ai.php:61`: the photo-vision model defaults to `gemma4:12b` whatever the provider is. Setting only `AI_PHOTO_VISION_PROVIDER=anthropic|openai|gemini` therefore sends an Ollama model id to the cloud API. **Fix:** default the model to `?: null` like the other features, and put the vision default on the ollama provider entry.
- `app/Services/PhotoExtractionService.php:83`: `PhotoExtractionTarget::$provider` is ignored. The job runs the stored model on whatever provider is active when it runs, so `photo_extractions.provider` can be wrong. The unique key also leaves out provider. **Fix:** run on `$target->provider` (or fail when it differs), add provider to the unique key, and drop the unused `$extractionId`.

### Minor

- `app/Services/PhotoLabService.php:91-93`: the in-flight check and the re-queue are not atomic, so concurrent POSTs can dispatch two jobs for one row. **Fix:** use a conditional `UPDATE ... WHERE status NOT IN ('queued','running')` and dispatch only when a row was affected, and add `ShouldBeUnique` keyed by extraction id.
- `resources/js/ai/Pages/Lab/Photos.vue:70`: `request_failed` can never light, because `errorOf` and `abandon()` always store `{error: [...]}`. **Fix:** tell transport failures apart by the `error` key, or expose a failure kind (gap 14).
- `app/Repositories/EloquentPhotoLabRepository.php:44`: there is no switcher for other model and prompt-version rows. **Fix:** load the photo's other extraction rows into `PhotoLabDetail` and render them as a switcher (gap 13).
- `app/Jobs/ExtractPhotoJob.php:25`: the 300 s job timeout is shorter than 3 attempts at the 120 s HTTP timeout (360 s). **Fix:** raise the job timeout (and `retry_after`) above `MAX_ATTEMPTS ×` the provider timeout, or cap the per-call timeout.
- `app/Services/PhotoExtractionService.php:89`: the cloud budget counts one hit per request, but a job can make up to 3 paid calls. **Fix:** count `MAX_ATTEMPTS` hits on this route, or hit the limiter per attempt inside the job.
- `app/Services/PhotoImportService.php:90`: a missing GD extension is swallowed as "unreadable", and with `--fresh` the existing photos are already deleted by then. **Fix:** check for GD once before the loop, or catch only `unreadableImage`.
- `app/Services/PhotoImportService.php:51`: with `--limit`, the class matched and skipped counts cover only the classes before the cut. **Fix:** count every distinct class, independently of the limit.
- `resources/js/ai/Pages/Lab/Photos.vue:148`: polling stops for good after one failed status request. **Fix:** retry with backoff.
- `resources/js/ai/Pages/Lab/Photos.vue:240`: grid tiles load the full 1024 px JPEGs. **Fix:** store a roughly 320 px thumbnail at import time and expose it as a separate URL.
- `app/Support/PhotoImageResizer.php:46`: EXIF orientations 2, 4, 5 and 7 are not handled, and there is no sRGB conversion. **Fix:** add `imageflip` for the mirrored cases and handle colour profiles, or record the deviation.
