# Ship report: spec-20261111-2206-photo-text-search (SL-37, search car photos by text)

## Summary

SL-37 adds text search over car photos: `GET /api/photos/search`, the lab page `/ai/photo-search`, the `photos:search-eval` command and the guide at `/ai/guides/photo-search`. The server side works end to end and all four gates pass (1975 tests). It is not ready to ship. Three round-2 converge tasks (12, 13, 14) are still open, and the harness also counts task 4 as incomplete. The How it works panel misreports a refused query (task 13). The shipped `min_score` default (0.2) does not match the spec's binding calibration rule (0.15) (task 14). The work is uncommitted WIP on `master`.

## Acceptance

**Resolved end to end: no.**

The check ran live against https://ai-lab.ddev.site (frankenphp, the real photo-encoder sidecar, Postgres with 156 photo vectors).

What works:
- **AC-1, uncached search:** "red convertible" returned 200 in 1.58 s with 12 results from 12 distinct listings, best first, all at or above 0.2.
- **AC-4, cached search:** the repeat call took 24 ms, returned `cached=true` and wrote no `ai_runs` row.
- **AC-2, refusal (server side):** a refused query gets 422 `code: refused`, a refused run row is written and the encoder is not called.
- **Validation:** a `q` that is too short gets 422.
- **AC-6, lab page:** the page shows the prompt sent, the label, the cutoff and the source ("database", then "from cache"). Each card links to `/ai/photos?photo={id}`, which resolves.
- **AC-3 and AC-5:** both pass in tests.
- **Must-not-change and NFR checks:** MNC-1 to MNC-4 and NFR-1/NFR-2 hold. Uncached p95 is 136 ms and cached p95 is 0.97 ms. The asset fingerprint is unchanged.

Broken hops:
- **Journey 7 (AC-2 on the lab page):** on a refused query, How it works ticks all five steps, including the encoder and index steps. Cause: `resources/guides/photo-search.php` maps `refused` to step 4, and `useGuideSteps.activeStep` sets `completedThrough = 4`. This is open task 13.
- **AC-7:** `config/ai.php` ships `min_score` 0.2, but `run.json` and `PhotoSearchEvalScorer::choose` pick 0.15. `decisions.md` D-2 departs from the spec's binding rule without amending the spec. This is open task 14.
- **Build freshness:** `public/build/manifest.json` (23:08) was older than `PhotoSearch.vue` and `useSearchRequest.ts` (23:12), so the live page ran stale code until `ddev npm run build`.

Also seen:
- The guide's Numbers tab is still a "pending" entry that renders "not measured yetms", although `run.json` holds the p95 latency.

E2E regression test: none written. The E2E step returned no result, and no E2E test is traced to the AC ids. Browser acceptance was manual only.

## Confirmed review findings

### Major

- `app/Services/PhotoTextSearchService.php:99`: no Server-Timing is recorded, so the lab page's Embedding and Database tiles are always empty. (Two reviewers reported this one; it is merged here.) Fix: inject `App\Support\ServerTiming` and wrap `embedText()` in `measure('embed', ...)` and `nearestToVector()` in `measure('db', ...)`, as `SemanticSearchService` does.
- `app/Repositories/EloquentPhotoTextSearchRepository.php:22`: `nearestToVector()` is a near-verbatim copy of `EloquentSimilarPhotosRepository::nearest()`. Fix: extract a shared nearest-by-vector-expression helper and call it from both.
- `app/Services/PhotoTextSearchService.php:135`: the code hard-codes SL-36's private key `similar-photos:generation:{label}`. Fix: expose the generation through a public method on `SimilarPhotosService` or a shared collaborator.

### Minor

- `app/Services/PhotoSearchEvalScorer.php:70`: `choose()` reports a calibrated threshold even when every objective is 0. Fix: return null, or flag the case, when the best objective is 0.
- `app/Repositories/EloquentPhotoSearchEvalRepository.php:40`: the newest extraction with empty `dominant_colours` is skipped, and photos with a completed extraction but no colours are dropped from the colour pool. Fix: always take the newest completed row and grade an empty result as not relevant.
- `app/Console/Commands/PhotoSearchEvalCommand.php:35`: a `--k` above the service limit of 12 is silently capped, so P@k is mislabelled. Fix: reject a `k` greater than `ai.photo_search.limit`, or record the effective k.
- `app/Exceptions/PhotoSearchRefusedException.php:15`: the class copies `NlSearchRefusedException`, including a message about "the assistant's instructions" that does not apply here. Fix: share a base refused exception and rewrite the message for photo search.
